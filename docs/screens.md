# 画面設計

> **状態: 骨子のみ。** 画面ごとの要素と遷移は、対応する機能の実装に着手する直前に詰める。
> 先に全画面を描いても、実装で必ず変わるためである。

## 画面一覧

|---|---|---|---|
| ログイン | `/login` | 不要 | メールアドレス・パスワード |
| サインアップ | `/signup` | 不要 | メールアドレス・ハンドル・表示名・パスワード |
| フィード | `/` | 必要 | フォロー中 / 新着 の切り替え |
| 投稿作成 | `/posts/new` | 必要 | 画像・本文・都道府県・訪問日・タグ・代替テキスト |

| 投稿編集 | `/posts/[id]/edit` | 必要 | 画像以外を編集 |
| プロフィール | `/users/[handle]` | 必要 | 投稿 / 旅行履歴 / 都道府県制覇マップ |
| フォロワー | `/users/[handle]/followers` | 必要 | フォローの導線付きの利用者一覧 |

## 共通の方針

- **未認証で認証必須の画面を開いた場合はログイン画面へ送り、認証後に元の画面へ戻す**
- 読み込み中・空・エラーの3状態を全ての一覧で用意する（「何も出ない」を作らない）
- 一覧はカーソルページネーションで追加読み込みする
- 状態は色だけで示さない。記号と文言を併記する

## 決まっていないこと

- タイルグリッドの各県の配置（行・列）。**データファイルに切り出し、見た目を見ながら調整する**
- 画像アップロード中の進捗表示の粒度
- 通知のリアルタイム更新をするか（初期はポーリングか、画面遷移時の再取得に留める）

## 決まったこと

- **都道府県制覇マップは地理的な地図ではなくタイルグリッドを自作する**
  （理由は [機能一覧](features.md) 8 章）
- **同じ見た目のボタンが並ぶ一覧では、読み上げ用のラベルに相手の名前を入れる。**
  フォロー一覧では「フォローする」ボタンが何個も並び、読み上げだけでは
  どれを押すのか区別できない。視覚的な文言は短いまま、
  `visually-hidden` で「○○をフォローする」を添える
- **プロフィールの制覇率は数と語で示し、地図の色分けに依存させない。**
  地図（8章）が入っても、この数値表示は残す
- **発見の検索条件は URL に載せる。** 画面の中だけに持つと、
  「この条件で見て」とリンクを送れず、戻る操作でも前の条件に戻れない
- **条件が1つも無いうちは結果を出さない。** 全件を並べても発見にはならず、
  何を探せばよいか分からない画面になる
- **未読は色だけでなく語（「未読」）と左の線でも示す。**
  ヘッダーの件数にも「◯件の未読」と語を添える。数字だけでは何の数か
  読み上げで分からない
- **通知のリアルタイム更新はしない。** 画面を移るたびに未読の件数だけを
  取り直す。常時つなぐ仕組みを持ち込むほどの機能ではなく、
  数だけの軽い問い合わせなら遷移ごとでも負担が小さい
