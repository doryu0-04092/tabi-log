# 進捗と残作業

最終更新: 2026-08-31

「何ができているか」ではなく **「次に何をすればよいか」** を書く。

## 見た目の方向

**レトロポスター**（2026-08-29 に決定）。70年代の旅行ポスターを下敷きにしている。

| | |
|---|---|
| 紙 | `#f6ecd8` — 白ではなくクリーム |
| カード | `#fffaf0` |
| 墨（線・文字） | `#1c2b2d` |
| 主色 | `#ad3b1c` |

要点は3つ。**ぼかした影を使わない**（墨の輪郭＋ずらしたベタ影）／**角を落とす**（4px、丸ボタンは使わない）／**細い灰色の罫を使わない**（2px の墨の線）。

- `--color-page` と `--color-bg` を分けてある。**分けないとカードが地に沈む**
- ロゴだけ Bungee（ラテン専用・十数KB）を読む。**本文には使わない**
  （日本語のウェブフォントは数百KBで、見た目の差に対して代償が大きい）
- 主色は「塗りの上に文字」と「面の上の文字色」の両方で使うため、
  **いちばん暗い面（--color-surface）を基準に明度を決める**。
  `#d1502f`（4.28:1）→ `#b8401f`（4.39:1）→ `#ad3b1c`（4.87:1）と2回下げている

## 作業の進め方（決まっていること）

| 項目 | 決定 |
|---|---|
| ブランチ | **既定ブランチへ直接コミットしない**（`guard-default-branch` フックが遮断する）。`git switch -c` してから作業する |
| マージ | **確認不要**（2026-08-28 に本人が許可）。ただし **CI が緑であることの確認は省略しない** |
| 生成物 | `docs/openapi.yaml` と `db/migrations` が正。`go generate ./...` と `npm run gen:api` で再生成し、CI が差分ゼロを検証する |
| 書式 | `.prettierrc` で明示。CI が `format:check` で検証する |
| lint | `golangci-lint run` を**手元で回してから push する**（CI で初めて気づくと往復が増える） |
| シェルスクリプト | 実行権限は `git update-index --chmod=+x` で明示的に記録する（Windows では `chmod` が反映されない） |

### この環境で繰り返し踏んだ罠

- **`resolve.conditions` に `[]` を渡すと Vite の既定を置き換える。**
  「指定なし」ではない。既定に含まれる `browser` が外れ、`svelte` が
  `index-server.js` に解決され、**`onMount` が no-op になる**。
  SvelteKit の `afterNavigate` は内部で `onMount` を使うため、
  移動を数える処理が一度も呼ばれず「前の画面へ戻る」が出なくなっていた。
  テスト側で同じ問題を踏んだときの対処として書かれた設定が、
  **もう片方に同じ穴を開けていた**（2026-09-01）。
  切り分けは「`$effect` は動くが `onMount` は動かない」で決まった
- **EXPLAIN は `Extra` だけでは足りない。`key` も見る。**
  並べ替えが出ていなくても、意図した索引ではなく PRIMARY を
  範囲走査していることがある。コメントの一覧が実際にそうだった
  （`key=PRIMARY / rows=4957 / filtered=20.17%`）
- **実行計画は種データの分布で変わる。** 1つの投稿にコメントを偏らせると
  PRIMARY を辿るだけで `LIMIT` が埋まり、索引の要否を判定できない。
  **偏りのない分布で測る**（400投稿 × 25件）。
  最初に偏った分布で測って「問題なし」と誤判定した（2026-09-01）
- **`image.Image` の `At` は1画素ごとに割り当てを起こす。**
  返り値が `color.Color` インターフェースのため箱に入る。
  5000万画素で 5000万回・200MB のごみになる。Lambda は memory_size 1024MB で、
  復号後の原本だけで 200MB を使うので効いてくる。
  `*image.RGBA` なら `Pix` を直接添字で触る（886ms/400MB → 235ms/200MB）
- **見た目の重なりは目視で判断しない。** 制覇マップのマス配置で、
  モックを見て「重なりなし」と判断したが、当たり判定を計算したら10組が
  重なっていた。**座標を持つものは計算で確かめる**（2026-09-01）

- **Git Bash はコマンドライン引数の日本語を壊す。** curl などへ日本語を渡すときは、
  ヒアドキュメントでファイルに書いてから `--data-binary @file` で送る
- **生成された構造体はフィールドがアルファベット順**。JSON から `"id"` を
  素朴に拾うと `author.id` を取ってしまう。取り出しは JSON として解析する
- **`zip` が入っていない。** Lambda のパッケージングは `cmd/lambdapack`（Go）で行う
- **カーソルを `id` にするなら、索引も `(絞り込みの列, id DESC)` にする。**
  `(user_id, created_at DESC)` は絞り込みには使えるが
  `ORDER BY id DESC` を解決できず `Using filesort` が出る。
  posts（000003）と notifications（000004）で同じ修正を2回した
- **E2E が増えると登録のレート制限に当たる。** 1回の実行で作る利用者は
  テスト数とほぼ同数で、失敗時の再試行でさらに増える。
  `.env.example` の `LOGIN_ATTEMPT_LIMIT` を引き上げる（本番は既定の 10）
- **楽観的更新のボタンは「押した」だけでは確定していない。**
  いいね・フォローは応答を待たずに見た目を変えるため、
  `aria-pressed` が変わっても送信中のことがある。画面を移る前に
  `waitForResponse` で待つ（`e2e/fixtures/app.ts` の toggleFollow / toggleLike）
- **`EXPLAIN` の `possible_keys` と `key` を取り違えない。**
  索引が「使われている」ことを確かめるつもりで候補一覧を見ていた。
  データが少ないうちは optimizer の選択が費用の誤差で決まるため、
  **`FORCE INDEX` で「その索引なら解決できるか」を見るほうが安定する**
- **先頭の列が同じ索引を2本持つと、並べ替えを解決できない側が選ばれる。**
  `(user_id, id DESC)` を足しても `(user_id, created_at DESC)` が残っていると、
  絞り込みの効き目は同じに見えるためオプティマイザが後者を選び、filesort が出る。
  **足すだけでなく、要らなくなった方を落とす**（000005 は落としており、
  000003 が落とし忘れていた）。落とせない場合（別の用途がある）は
  問い合わせ側で `FORCE INDEX` を書く。4か所で起きた
- **`go test` は既定でパッケージを並列に回す。** 同じデータベースを空にしてから
  使うテストが2つのパッケージにあると、互いのデータを消し合う。`-p 1` を付ける
- **テストを飛ばす条件を「CI かどうか」にしない。** CI にはデータベースを
  用意しないジョブもある。**用意した側が名乗る**形（`TEST_DB_REQUIRED`）にする
- **文章の中に「go:generate」「go:embed」と書くと指示行として解釈される。**
  staticcheck が SA9009 で落とす。かぎ括弧で囲む

**AWS へ上げてから踏んだもの（2026-08-31）**

- **`terraform apply` は zip を配るだけで、Go をビルドしない。** 古い
  `imageworker.zip` が残っていると、それがそのまま Lambda に載る。
  **apply は成功し、plan にも差分は出ない。** 気づけるのは画像を1枚
  上げてみたときだけ。`docker/bootstrap-deploy.sh` に工程として入れた
- **OIDC の `sub` には ID が埋め込まれている。**
  `repo:<所有者>@<所有者ID>/<名前>@<リポジトリID>:ref:refs/heads/main` の形で、
  名前だけで書いた信頼ポリシーとは一致しない。
  **CloudTrail の `AssumeRoleWithWebIdentity` の `userIdentity.userName`**
  に実際に送られた値が入っている。ここを見るまで原因が分からなかった
- **Lambda の同時実行は「予約できない」ことがある。** アカウントの上限が
  10 だと、AWS は「予約していない枠を 10 未満にできない」ため1つも予約できない。
  **plan は通り、apply で落ちる型**である
- **PowerShell の `bash` は WSL の bash に解決される。** Git Bash を明示する
  （`& "C:\Program Files\Git\bin\bash.exe" ...`）
- **保存した plan には秘密が平文で入る。** アプライ済みの状態から取ると、
  現在の DB パスワード・JWT の署名鍵・CDN の秘密鍵が含まれる（16件あった）。
  `.gitignore` は**接尾辞ではなく接頭辞で捉える** — `tfplan` は除外していたが
  `tfplan-destroy` が素通りして一度コミットした
- **負荷試験の setup がログイン試行の上限をちょうど使い切る。** 利用者10人ぶんの
  トークンを取るため、**2本目以降が必ず 429 になる**。
  `login_attempt_limit` を上げてから測り、**測り終えたら戻す**
- **bcrypt のコストは開発機で見積もらない。** cost=12 は開発機で 180ms、
  Fargate 0.5 vCPU では約1050ms。**「数十ミリ秒の増加」という見積もりが
  そのまま本番の1秒になっていた**
- **コストを変えても既存の利用者は取り残される。** bcrypt はコストを
  ハッシュ自体に記録するため、設定を変えても古いハッシュは古いまま検証される。
  **ログイン成功時に付け直す**仕組みが要る
- **Wikimedia Commons にはモンタージュ画像がある。** 都市の紹介用に複数写真を
  1枚に合成したもので、検索の上位に出る。名前だけ見て採ると
  「1枚のはずが何枚も写っている」状態になる。ファイル名と縦横比で弾く
