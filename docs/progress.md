## 次にやること（features.md の順序）

### 1. フォロー中フィード（features.md 5章）

新着フィードは実装済み。**フォロー中フィードが未実装。**

> ⚠️ `WHERE user_id IN (SELECT followee_id FROM follows WHERE follower_id = ?)`
> はフォロー数が増えると劣化する。想定は1人あたり平均200フォロー。
> **ここは負荷試験の対象**として設計書に挙げてある。

### 2. 発見（features.md 6章）

- 都道府県で絞り込み / タグで絞り込み / **キーワード全文検索** / ユーザー検索 / 人気順
- **`PostSearcher` インターフェースを作るのはここ。** 初期実装は MySQL の
  ngram FULLTEXT。実測で厳しければ OpenSearch へ差し替える前提
- **検索クエリだけ sqlc の外に出す。** 条件が可変で AND が増減するため
  sqlc では扱えない。`database/sql` で手書きし、値は必ずプレースホルダに
  バインドする（ユーザー入力を SQL 文字列に連結しない）

### 3. 通知（features.md 7章）

- **書き込み側は済んでいる。** いいね・コメントの通知は、契機となる操作と
  同一トランザクションで INSERT する形で3章に入れた（取り消し時の削除も含む）。
  **同一トランザクションであることが設計の要点であり、後から足せないため。**
  残りは**読み取り側**（一覧・未読数・既読化）とフォローの通知
- `delivered_at` 列は既にあるが未使用（将来のプッシュ通知用）

### 4. 都道府県制覇マップ（features.md 8章）

- **地理的な地図ではなくタイルグリッドを自作する**（決定済み。理由は features.md 8章）
- 配置（各県の行・列）は**データとして1ファイルに切り出す**
- 集計は `SELECT DISTINCT prefecture_code FROM posts WHERE user_id = ?`
  （索引 `ix_posts_user_prefecture` は投入済み）
- 色分けだけに頼らず、同じ情報を表形式でも出す

### 5. プロフィール周辺（features.md 1.3〜1.5）

**表示は済んでいる。** 残りは編集系。

- プロフィール編集（表示名・自己紹介・アバター）、パスワード変更、退会
- 旅行履歴（訪問日順）の切り替え。投稿一覧（投稿日順）だけが実装済み
- **パスワード変更時はそのユーザーの全リフレッシュトークンを失効させる**
- 退会は物理削除ではなく匿名化 + 関連データ削除（手順は er-diagram.md の `users`）
- **S3 のオブジェクトも明示的に消す**（外部キーの連鎖削除では消えない）

### 6. AWS へのデプロイ

`infra/` はまだ空。[AWS構成設計](aws-architecture.md) に構成は書いてあるが
Terraform のコードは未着手。

- CloudFront + S3×2 + ALB + Fargate + RDS + **画像処理 Lambda + S3イベント通知**
- **CI に `terraform fmt -check` / `validate` のジョブを足す**
  （現在は検証対象が無いため意図的に入れていない）
- RDS の提供状況は確認済み（MySQL 8.4.9 / db.t4g.small / gp3 が利用可能）

### 7. 負荷試験

- 想定規模: ユーザー2000 / 投稿20万件 / ピーク50 req/s
- **シードは段階的に投入**（2万 → 20万）し、各段階で測る
- **DB のレコード数と S3 の実データ量は切り離す** —
  20万件を額面どおり画像付きで作ると S3 だけで月$15前後の課金になる

Dependabot の PR 7件は処理した。未処理の PR は無い。

- **6件はマージ済み** — Actions のメジャー更新（checkout/setup-go/setup-node/
  upload-artifact/golangci-lint-action）と alpine 3.22→3.24

  7 に置き換えるだけ）は形が違ったため閉じ、`svelte-check` が案内する構成に

      typescript@~6  +  @typescript/native（typescript@7 の別名）
      svelte-check に --tsgo を渡す

  両方が必要になる。**型エラーと a11y 警告を従来と同一に検出することを
  実測で確認した**（ルートファイルを含む）。

## 作業の進め方（決まっていること）

| 項目 | 決定 |
|---|---|
| ブランチ | **既定ブランチへ直接コミットしない**（`guard-default-branch` フックが遮断する）。`git switch -c` してから作業する |
| マージ | **確認不要**（2026-08-28 に本人が許可）。ただし **CI が緑であることの確認は省略しない** |
| 生成物 | `docs/openapi.yaml` と `db/migrations` が正。`go generate ./...` と `npm run gen:api` で再生成し、CI が差分ゼロを検証する |
| 書式 | `.prettierrc` で明示。CI が `format:check` で検証する |
| lint | `golangci-lint run` を**手元で回してから push する**（CI で初めて気づくと往復が増える） |
| シェルスクリプト | 実行権限は `git update-index --chmod=+x` で明示的に記録する（Windows では `chmod` が反映されない） |

### この環境で繰り返し踏んだ罠

- **Git Bash はコマンドライン引数の日本語を壊す。** curl などへ日本語を渡すときは、
  ヒアドキュメントでファイルに書いてから `--data-binary @file` で送る
- **生成された構造体はフィールドがアルファベット順**。JSON から `"id"` を
  素朴に拾うと `author.id` を取ってしまう。取り出しは JSON として解析する
- **`zip` が入っていない。** Lambda のパッケージングは `cmd/lambdapack`（Go）で行う
