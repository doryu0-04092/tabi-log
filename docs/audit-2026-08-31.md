## 高（4件）

### H1. `originals/` のライフサイクル削除が確定済みの原本にも効く【照合済み】

`infra/s3.tf` のルール `expire-unconfirmed-originals` は、**名前に反して
`prefix = "originals/"` しか条件に持たない。**

```hcl
rule {
  id = "expire-unconfirmed-originals"
  filter { prefix = "originals/" }
  expiration { days = var.orphan_expiration_days }   # 既定 7 日
}
```

**投稿に使われた原本も 7 日で消える。** 残るのは JPEG q82・長辺 1080 の変換物だけで、
元に戻せない。

`docs/er-diagram.md` の「kind を増やせば別解像度を後から追加できる」と矛盾する。
`store/posts.go` は削除時に原本キーも対象にしており、**原本が残る前提で書かれている。**

### H2. Lambda が失敗し続けると `media` が pending のまま残る【未照合】

S3 → Lambda は非同期で、再試行 2 回のあと破棄される。
`infra/lambda.tf` に `event_invoke_config`（DLQ / on-failure）が無い。
画面は 22 秒で諦める（`frontend/src/.../posts.ts`）が、**拾い直しも検知も無い。**

⑪「実行予定フラグの喪失」に該当する。

> 推測: 向き補正が画素ごとの `At`/`Set` で、5000 万画素の上限だと
> 1024MB の Lambda で 60 秒 timeout を超えうる（**未計測**）。

### H3. presign にレート制限が無い【未照合】

認証済み利用者が S3 PUT・Lambda 起動・DB 接続を無制限に起こせる。
Lambda に `reserved_concurrent_executions` が無く、
`infra/rds.tf` の接続数 precondition は **ECS しか数えていない。**

> 推測: micro（max_connections ≈ 85）で 1 タスク × 25 + 同時 Lambda 60 で枯渇（**数字は推測**）。

### H4. `/api/docs` が外部 JS を SRI 無しで同一オリジンに読む【照合済み】

```html
<script src="https://cdn.jsdelivr.net/npm/swagger-ui-dist@<version>/swagger-ui-bundle.js"></script>
```

`integrity` 属性が無い。CSP も全経路に無い。

**CDN 側が改ざんされると、同一オリジンから `POST /api/auth/refresh` を呼べる。**
CSRF ヘッダーは固定文字列なので防げず、閲覧中の利用者のアクセストークンが取られうる。

## 扱い方

**この一覧は「直すもの」ではなく「判断の材料」である。**

学習用の構成として意図的に割り切っている項目（L7・L9 など）と、
本番なら直すべき項目（H1・H4・M1）が混在している。
**一律に潰しにいくと、割り切りとして決めたことまで巻き戻すことになる。**

優先順位を付けるなら、次の順が妥当と考える。

1. **H1** — データが不可逆に失われる。しかも**設計書と矛盾している**
2. **H4・M1** — 秘密の露出経路
3. **L10** — 文書と実態のずれ。**放置すると他の判断の土台が狂う**
4. H2・H3・M3 — 動かしてみないと影響の大きさが確定しない
