# テスト計画

> **状態: 各層とも実装済み**（2026-08-30 時点）。
>
> | 層 | 件数 | 回すタイミング |
> |---|---|---|
> | バックエンド単体・結合（偽の実装） | 239（サブテスト込みで 330） | 毎回（CI） |
> | バックエンド（**実際の MySQL**） | 上記に含む | 毎回（CI の専用ジョブ） |
> | フロントエンド単体（Vitest） | 30 | 毎回（CI） |
> | E2E（Playwright + axe-core） | 130（ほかに1件を仕様変更で保留） | 毎回（CI） |
> | 負荷（k6） | 4シナリオ | **構成やデータ量を変えたときだけ**（CI から除外） |

> 件数は 2026-09-01 に数え直した。数え方は次のとおり。
>
> - バックエンド: `go test -v ./...` の `--- PASS` を、行頭のものと字下げされたもので分けて数える
> - フロントエンド単体: `vitest run` の Tests
> - E2E: CI の Playwright の出力（passed と skipped）

## 層ごとの役割

| 層 | 使うもの | 何を確かめるか |
|---|---|---|
| バックエンド単体 | Go 標準 `testing` | 分岐・境界値・エラー時の振る舞い。データベースを必要としない部分 |
| バックエンド結合 | `testing` + Docker の MySQL | SQL の正しさ、**トランザクション境界**、外部キーの連鎖削除、**実行計画（索引で ORDER BY まで解決できているか）** |
| フロントエンド単体 | Vitest | API クライアントのエンベロープ解釈とエラー分類 |
| E2E | Playwright | 実際に配信されるビルド成果物に対する主要導線 |
| アクセシビリティ | Playwright + axe-core / svelte-check | 自動で検出できる違反。**警告を CI のエラーとして扱う** |
| 負荷 | **k6**（`perf/`） | 想定規模での応答時間と、壊れ始める点。**毎回は回さない** |

## 必ずテストで担保する項目

実装の都合で崩れやすく、崩れたときの影響が大きいものを挙げる。

| 項目 | 理由 |
|---|---|
| **livez が DB 停止時も 200 を返すこと** | 崩れると DB の一時的な不調で全タスクが置き換えられる |
| **認可（自分の投稿のみ編集・削除できる）** | フロントエンドの制御だけでは守れない |
| **カウンタ列と本体の更新が同一トランザクションであること** | いいね数がずれる |
| **通知の INSERT が契機の操作と同一トランザクションであること** | 「いいねはされたが通知が来ない」 |
| **リフレッシュトークンのローテーションと盗用検知** | 並行リフレッシュで正常な利用者がログアウトされる |
| **EXIF の GPS 座標が除去されていること** | 位置情報の漏洩に直結する |
| **`processed` でないメディアを含む投稿を作成できないこと** | 上記の除去を迂回する経路になる |
| **日本語のキーワードで全文検索がヒットすること** | パーサ設定を誤ると一切ヒットしない |

## 生成物の検証（自動テストでは捕まらない領域）

sqlc・oapi-codegen・openapi-typescript・Terraform の plan は
「入力から成果物を生成する仕組み」であり、**ビルドもテストも通るのに内容が誤っている**
ことがありうる。

| 対策 | 内容 |
|---|---|
| CI で再生成の差分ゼロを検証 | 仕様を変えて再生成を忘れる、を止める |
| **最初の1件は必ず目視する** | 同じ書き方を多数へ広げる前に、生成結果を人が読む |
| 成果物に対するテスト | 例: 全エンドポイントに 2xx のレスポンスが定義されていること |

前回プロジェクトでは、注釈の解釈違いにより
**「成功レスポンスが存在しない」API 仕様書**が生成された。
コンパイルもテストも UI の描画も通り、生成された JSON を目視するまで気づけなかった。

## 実行方法

```bash
cd backend  && go test ./...
cd frontend && npm run check && npm run lint && npm test && npm run test:e2e
```

CI では上記すべてに加えて `govulncheck` と `npm audit` を実行する。
